# UI/UXレビュー報告: 詳細プレビューモーダルのワイド表示

## 1. 概要

- 対象: Issue #581
- 変更したUI: WordPack、例文、文章の詳細プレビューモーダル
- ユーザー価値: 長い例文や詳細情報を、モーダルを閉じずに横へ広げて確認できる
- 判定: Pass（ローカルUI/UXゲート。マージ可否はPRのCIとレビューで別途確認する）
- 未対応P0: 0件

## 2. 仕様と判断

- デスクトップの詳細プレビューだけに「ワイド表示」を追加した。確認ダイアログなど、内容閲覧が目的でないモーダルには表示しない。
- 標準の最大幅は900px、ワイドの最大幅は1800pxで、標準の正確な2倍とした。
- どちらも `96vw` を上限とし、画面外への横はみ出しを防ぐ。960px以下では、実質的な幅の差が小さく操作を増やすだけになるため切替を非表示にする。
- 切替状態はモーダルを閉じると標準へ戻す。別の詳細を開いた際に、前回の一時的な閲覧設定を持ち越さないためである。

## 3. state matrix

| 状態 | ユーザーが見るもの | 操作・回復 | a11y / 構造 | 証跡 | 判定 |

## 4. アクセシビリティと効率

- 切替はnative `button` とし、マウス、Tab、Space / Enterで操作できる。
- 状態は色だけでなく `aria-pressed` でも伝える。ワイド時の実画面で可視フォーカスを確認した。
- 既存のdialog名、フォーカストラップ、Escape、閉じた後のフォーカス復帰は共通 `Modal` の契約を維持する。
- 閲覧中の文脈、スクロール位置、入力内容を保ったまま1操作で幅を切り替えられる。
- モバイルでは効果の小さい切替を見せず、既存の縦方向の閲覧に集中させる。

## 5. 視覚・コピー・信頼

- 切替は閉じる操作と同じヘッダー右側に置き、内容操作とは分離した。
- ラベルは結果を直接示す「ワイド表示」とし、内部のpx値をユーザーへ露出しない。
- 押下状態では既存アクセント色を使い、テーマと一貫させた。
- 画面幅が足りない場合に2倍を強制せず、viewport上限を優先する挙動をマニュアルに明記した。

## 6. 反証レビュー

| 観点 | 見つけた問題 | 対応 |
|---|---|---|
| 状態持越し | 一度ワイドにすると再表示時もワイドのままでは、予期しない横幅になる | close / reopenで標準へ戻す回帰テストを追加 |
| 狭幅 | 2倍幅がviewportを超える、または効果のない切替が残る | `96vw` 上限と960px以下の非表示をE2Eで確認 |
| 既存モーダル | 共通Modalへの追加で確認ダイアログにも切替が出る可能性 | opt-in propと非表示の回帰テストを追加 |
| 操作認識 | 色だけのpressed表現になる可能性 | `aria-pressed` とnative buttonを採用 |
| ヘッダー圧迫 | 長いタイトルが切替・閉じるを押し出す可能性 | タイトルを折返し可能、操作群を縮小不可にした |
| 画像証跡の偽陽性 | 未モックの語句ルックアップが401になり、dialogが閉じた画像でもsnapshot更新が成功し得た | 補助APIを404へ固定し、dialog本文が残ることを目視して通常比較を再実行 |
| 内側コンテンツの固定幅 | 外枠だけを1800pxへ広げても、例文詳細の58rem上限により余白だけが増える可能性 | 固定上限を除き、例文本文が標準時の1.9倍超かつワイド外枠の95%超へ広がることを実ブラウザで測定 |

## 9. 残るリスク

- 1800px未満の表示領域ではviewport上限が優先されるため、見た目の幅が常に厳密な2倍になるわけではない。横はみ出しを防ぐための意図した制約である。
- 実スクリーンリーダーと実ユーザーによる理解度は未確認である。
